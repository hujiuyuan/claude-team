# 通用关注点清单

**定位**：这十类是**任何后端设计都要过一遍**的横切关注点。不是「项目涉及才写」——每份设计文档必须逐类显式回答，哪怕答案是「本次不涉及，因为 X」（要写出 X 是什么，不许留空）。留空的那类，就是将来线上出事的地方。

每类三样：**何时必答** / **要写清什么** / **判据**（怎么算写对了）。

---

## 1 金额 · 精度 · 舍入

**何时必答**：凡涉及钱、数量、费率、折扣、分成、积分、对账。

- 存什么类型（`BigDecimal` / 分整数），**禁止 `double`/`float`**
- 单位是分还是元，在哪一层换算——**只在一个地方换**，别到处乘 100
- 舍入规则谁定：四舍五入 / 银行家舍入 / 向下取整；定在哪个粒度（每步还是最终一步）
- 多步计算（费率×金额 → 折扣 → 税费）中间结果保留几位——**每步都舍会漂移**

**判据**：同一笔金额在页面 / 接口 / 对账文件三处输出逐字一致；`0.1 + 0.2` 不出现 `0.30000000000000004`。

## 2 时区与时间

**何时必答**：凡存时间、按日期切、定时触发、有跨时区用户。

- 存储用 UTC 还是本地，列类型（`timestamptz` 还是 `timestamp`）
- 「当天」「本月」以谁的时区切，展示层在哪转
- 定时任务 cron 的时区基准写死哪个时区
- 时间比较一律在同一时区做完再比

**判据**：跨时区用户看到的是同一时刻；「当日 0 点」这条过滤在所有入口取到同一批数据。

## 3 缓存

**何时必答**：凡读多写少、跨请求复用、有热点数据。

- 缓存键怎么定（含不含租户 / 语言 / 版本号——**漏租户就是跨租户串数据**）
- TTL 多久；主动失效还是被动过期
- 穿透（查不存在的也缓存空值或布隆）/ 击穿（热点加锁或不过期）/ 雪崩（TTL 加抖动）各怎么防
- 允许读到多旧的数据（缓存与 DB 不一致的业务容忍度）
- 谁清缓存、清完多久生效

**判据**：缓存整体挂掉，主流程仍**正确**（只是变慢），不丢数据不串数据。

## 4 性能与容量（NFR）

**何时必答**：每个对外接口、每个批处理任务。

- 目标 QPS / 单请求延迟预算（P99 多少毫秒）——写数字，不写「尽量快」
- 数据量增长预估、单表行数上限；大表查询走哪个索引
- 批量上限（一次最多处理多少条），超了怎么办（分页 / 分片）
- 慢查询怎么发现（慢 SQL 阈值 + 谁看）

**判据**：给出的是**能压测的数字**，压不出来就是没写。

## 5 可观测性

**何时必答**：每个新增的入口、任务、关键链路。

- 埋什么指标：成功数 / 失败数 / 耗时分布 / 排队深度 / 积压量
- 告警阈值（连续 N 次失败 / 错误率超 X%）和告警对象（谁被叫醒）
- 关键日志必带：traceId · 租户 · 业务单号 · 关键字段（已脱敏）
- 健康检查暴露什么、挂了怎么被发现

**判据**：出问题后不看代码、只看监控和日志，能定位到「哪一步慢 / 失败 / 错」。

## 6 存量数据迁移与回填

**何时必答**：凡动表结构、改口径、改枚举含义。

- 加 NOT NULL 列走「加可空 → 回填 → 收紧」三步，还是直接默认值（默认值会掩盖真实数据）
- 回填脚本**幂等**、**可重跑**、**分批**（避免长事务锁表）
- 大表 DDL 用在线变更还是停机窗口
- 按旧口径落库的存量，要不要订正、谁订正、订正脚本可逆吗

**判据**：迁移脚本在空库和满库都能跑通；连跑两遍结果不变（幂等）。

## 7 上线与回滚

**何时必答**：每个变更都要，不只是大改。

- 部署顺序：先库后代码还是先代码后库，新旧代码能不能并存（不并存就是强制停机）
- 回滚方案：代码怎么回、DDL 回不回（多数 DDL 回不了）、要不要双写过渡
- 灰度 / 开关：feature flag 在哪、关了之后旧行为完整保留吗
- 数据变更（迁移、订正）单独排，和代码发布分开还是同批

**判据**：任何一步出错都有**明确的回退路径**，不是「重新部署一次再试」。

## 8 API 兼容与版本化

**何时必答**：凡改**已有**对外接口（新增接口不算）。

- 加字段算不算破坏（老客户端读不读得懂）
- 删 / 改字段怎么过渡：先加新弃用旧 / 版本号（/v1 /v2）/ 灰度
- 枚举加值会不会让下游的穷尽断言爆炸
- 弃用旧字段要留几个版本才删

**判据**：老客户端不升级，行为与升级前一致。

## 9 限流与防重放

**何时必答**：凡对外暴露端点——尤其回调、登录、验证码、公开接口。

- 限流阈值：单租户 / 单 IP / 单接口各多少
- 回调验签之外，有没有防重放（时间戳窗口 + nonce 判重）
- 限流触发返回什么（429？），会不会误伤合法流量、误伤后怎么恢复
- 幂等键之外，同一请求被重放多次会怎样

**判据**：同一请求重放 N 次，只有第一次生效，其余被安全拒绝且不产生副作用。

## 10 消息乱序与堆积

**何时必答**：凡走消息队列 / 事件 / 发件箱。

- 消费者能不能乱序；**同一实体**的消息要不要按序，怎么保证（分区键 / 单队列）
- 堆积：消费能力、积压告警阈值、死信谁来捞
- 投递语义：至少一次 + 幂等，还是恰好一次；丢一条 / 重一条业务能不能对账发现
- 重复消费、乱序、丢消息三者各走一遍，结果对不对

**判据**：消息乱序 / 重复 / 丢一条任意发生，业务结果仍正确**或**能被对账发现。
