# 设计文档

**真理源边界**：设计文档是「是什么」的唯一真理源。接口签名、字段表、建表语句只能写在这里。

### 🔴 一条决定成败的写法：**已有的东西不抄签名，只给路径**

文档里每写一个方法签名，就是一次「我说的」。而**「我说的」默认是错的，除非当场打开文件核过**——真实项目里在被当成唯一真理源的那一节，凭印象编出过一个错签名（返回类型、参数类型、包路径三样全错），而同一行还写着「照抄它」。

**所以按「代码里有没有」分两种写法**：

| 情况 | 怎么写 | 为什么 |
|---|---|---|
| **仓库里已经有的**（现成的工具类、DAO、发号器、锁）| **只给 `包路径/文件名` + 一句话说它干什么 + 「照它抄」。不抄签名。** | 抄了就有两个后果：写的时候可能抄错，写对了也会随代码演进而漂。**读的人能打开那个文件，让他看真声明。** |
| **本次要新建的**（还不存在的接口）| **必须写全签名与字段表** | 代码里没有，不写他就得猜 |

**判据很简单：这个东西现在 grep 得到吗？grep 得到就别抄签名。**

🔴 **必须单开一节「跨任务共用的接口速查」，并让每个任务书都点名它。**
派活规则是「只给他那一节 + 它点名的设计小节」——**他读不到别人的任务书**。可他要调别人产出的接口（开单、入账、读配置、建人工任务、发号……）。这些签名如果散在各任务书里，他只能猜方法名、猜参数、猜返回值。**真实盲测里这是最高频的一类卡壳。**
那一节要收：每个跨任务调用的**完整签名 + 谁产出**、**实体类的命名规则**（表名转驼峰这种，写清楚就不用等别人先合并）、以及**全局时序约定**（比如上下文该在开事务前还是后）。

⚠️ **不许把字段表 / 建表列清单推给另一份文档。**「完整 DDL 见某某汇总文档」这种写法，在那份文档不属于派活范围时等于没写。汇总文档是**落地后的归档去处**，不是干活时要读的东西——两者别混。
**不许写**：任务顺序、改哪些文件、完成判据——那些是执行手册的地盘。

头部固定记三个指纹：PRD 的 sha256 · 代码仓库 commit · 上一轮产物路径。

## 0 · 一句话结论

开门见山说清三件事：**现在到哪一步了**、**真正拦路的是什么**、**这份文档决定了什么**。

反例："本文档描述了订单支付模块的设计方案。" —— 零信息。
正例："七张资金表已经建好了，但 Java 侧一行代码都没有；真正拦路的是六件事，其中三件必须先拍板。"

## 1 · 术语表

收词判据与四列形状见 `writing-shapes.md`。**只收三类词**：项目自造概念、业务黑话、通用技术词但本项目有特定含义或坑。读者基线内的（什么是接口、什么是索引）一律不收。

## 2 · 现状核对

固定四列：`任务 | 现状 | 证据 | 还剩什么`

- 现状只有三档：✅ 已完成 / 🟡 一半 / ❌ 零代码
- **证据必须是文件路径 + 行号 + 原文引用**，路径从仓库根算起。写不出证据的不许标 ✅
- "还剩什么"要具体到可执行，不写"待完善"

**不信台账摘要。** 台账说没做的可能已经落地（去看迁移脚本），台账没标风险的可能缺一整块地基（去看类注释里的"本模块不负责 X"）。

## 3 · 阻碍

按五级分组，每级一小节。分级规则、判错代价、候补五要素见 `deferral.md`。

每条阻碍固定四段：**事实**（带证据原文）→ **后果**（不解决会怎样，尽量量化）→ **选项**（2~3 个，每个标代价）→ **处置**（选了哪个、为什么，或"要谁拍板"）。

⚪ 口径陷阱那一节写法特殊：这些错**都不报错**，只会在某天两处对不上。每条按坑的三段式写（症状 / 原因 / 正确写法），见 `writing-shapes.md`。

## 4.0 · 入口与生命周期 —— 设计正文第一节

```
4.0.1 本次涉及的入口清单     六类逐个列，用不到的写明"本次无"
4.0.2 每个入口的十阶段        第 3/5/9/10 四格必答，其余不适用可合并一行
4.0.3 出站远程调用清单        超时 / 重试次数 / 重试是否幂等 / 对端挂了怎么办 / 对端限流
4.0.4 反查表                 每个新增单元 ← 哪些入口能到达
4.0.5 多入口交集              被两个以上入口到达的单元，约束取最严的那个
```

详见 `entry-points.md`。**这一节写不出来，后面几节全是空中楼阁。**

## 4.1 · 分层与事务边界

- 沿用仓库现有分层，先去读架构约束测试（如果有）——它比任何文档都硬
- 事务口径写清三件事：**谁开事务** / **传播行为**（自己开 vs 借调用方的）/ **行级安全的租户值在哪设**
- 特别交代：哪些方法**不许自己开事务**（批量处理里的单条逻辑、编号生成）

架构约束常常直接决定结构。例如"同层的 public 方法禁止互调"这条，会逼着把跨模块共用的事务边界单独立成一个接口，而不是挂在某个服务实现的 public 方法上。这类推导要写出来，别只给结论。

## 4.2 · 数据结构

三部分：

**枚举**——`| 枚举 | 值 | 依据 |`。依据必须指回 PRD 出处或迁移脚本列注释。
值域**以 PRD 原件为准**，不要照有损导出的中间文档写——那里常常只列了种子数据里出现过的值，不是声明的值域。

**建表语句**——完整可执行的 DDL，带列注释。列注释里写清"为什么是这个形状"，尤其是选了 JSON 列而不是拍平成多列这类决定。
**不动已跑过的迁移文件**，订正列注释靠新迁移里的 `COMMENT ON COLUMN`。

**出入参字段表**——`| 字段 | 类型 | 含义 | 可空 | 取值来源 |`。
这是 `S`/`M`/`L` 三档都不许省的一格：只给接口签名不给字段表，新人写不出第一行。

**五条硬规则，每条都是被盲测卡住过才写下来的**（缺陷目录见 [blind-test.md](blind-test.md) A 类）：

1. **第一列必须是代码里真实的名字**——JSON 键名或 Java 字段名。中文只许出现在「含义」列。
   写「订单号 / 费用项目名」而不是 `orderNo` / `typeName`，对面做穷尽校验时键名对不上，**整单作废且失败是静默的**。
2. **类型必须是单一确定类型。** 不许写「字符串 **或** 键值对」——强类型语言里表达不了，写代码的人只能自己发明一个形状。
   真的有多种互斥形态时，用**封闭类型**（`sealed interface` + 几个 `record`）把互斥性交给编译器，别用「一个对象上几个可空字段」——那样非法组合能构造出来，只能靠人看。
3. **不许把字段表推给另一份文档。** 「完整 DDL 见 `02-1`」这种写法，在那份文档不属于本任务可读范围时，等于没写。要么写在这里，要么确保它在派活范围内。
4. **新建表要给列名、类型、可空三样**，不能只给「这张表要能存 XX」这种概念列。
5. **表里的字段形状要跟业务规则对得上。** 业务说「附件是数组、至少一张」，建表就不能给单数的一对列——这种自相矛盾会让人推翻整个建模假设。

**分层标注**：同一节里如果既有「外部打进来的 HTTP 请求 / 返回给外部的响应」，又有「我方内部调某一层时的出入参」，**每张表都要标清是哪一层**，并在节首说明分层。
⚠️ 标了分层就**必须把每一层的表都写全**——写了「某某任务要看的是内部那几张」却只给了其中两张，**比不标更糟**：明确告诉他别看这个要看那个，而那个是空的。

金额与时间字段在这一格直接写死类型和单位：金额用 `BigDecimal` 还是分整数、舍入规则；时间存 UTC 还是本地、时区基准。禁止 `double`/`float`、禁止「以服务器本地时间为准」这类模糊话。存量的加列、回填、订正也落在这里（见 `cross-cutting.md` 第 1、2、6 类）。

## 4.3 · 核心接口

**粒度：接口签名 + 出入参字段表 + 关键方法的分步伪码。不写方法体实现。**

**分步伪码里凡是列举，必须逐项给处置**（缺陷目录 E 类）：
- 「校验四项」→ 四项各自不通过时怎么办，不许只写典型的那一项
- 「状态守卫」→ 所有可能进来的状态各走哪条路，不许只写放行的那两个
- 有成功/失败两个分支 → 两个分支各要做什么都写，不许只写失败分支
- 有「上限 / 阈值」→ **说清 `0` 是什么意思**（不限？还是一次都不许？）

伪码写成带编号的步骤，每步一句话，标出哪几步在同一个事务里、哪几步在事务提交之后。例：

```
① 幂等查重   按 (A, B, C) 三列查，命中已成功的直接返回
② 落记录     新增一行，永远不改既有行
...
⑧ 触发下游   走事务提交后的钩子，不与 ①~⑦ 共存亡
```

伪码之后补**边界**：哪一步失败要怎么办、哪些失败不许回滚（钱已经收了）、哪条路径走另一个分支。

## 4.4 · 链路图

判据：**只涉及一个对象、几个分支 → 流程图；两个以上参与者、有明确先后 → 时序图。**
时序图**必须带失败分支**，用显式注释分隔。详见 `writing-shapes.md`。

## 4.5 · 对外接口清单

`| 方法 + 路径 | 干什么 | 出参 |`

- 路径写全（含统一前缀由谁加）
- 出参形状**跟已经存在的下游契约逐字对齐**，对不齐的要说明谁改
- 匿名端点、权限点、防枚举纪律这类约束跟在表后，不要漏
- **改已有接口**额外交代向后兼容：老客户端不升级能不能照常工作、删/改字段怎么过渡、枚举加值会不会让下游穷尽断言爆炸；对外端点补限流与防重放。见 `cross-cutting.md` 第 8、9 类

## 4.6 · 定时任务 / 错误码段位 / 权限点

三样都是**"不登记就报错"**的登记表，最容易漏：

- 定时任务：`| 任务 | 干什么 | 判据 |`，判据里写清过滤条件的边界（写宽了会误伤什么）
- 错误码：先查各段位已用到的最大值，本次取哪一段起。**先写抛出点再声明码**——很多项目会断言"声明了的码必须真的有人抛"
- 权限点：菜单键 + 按钮键都要列。哪两颗键**不能合成一颗**（提交与审核必须分开）要写明

## 4.7 · 通用关注点

十类横切关注点：金额精度 · 时区 · 缓存 · 性能与容量 · 可观测 · 存量迁移 · 上线回滚 · API 兼容 · 限流防重放 · 消息乱序。

**`M`/`L` 档逐类显式回答**——不涉及也写「本次不涉及，因为 X」，不许留空；留空的那类就是将来线上出事的地方。每类「何时必答 / 要写清什么 / 判据」见 `cross-cutting.md`。

`S` 档不出本文档，这十类改为**只答跟本次改动直接相关的那几类**，落在执行手册该任务第 7 段「本任务的坑与关注点」里。判据同「入口四格必答」：与改动无关的不必逐类写「不涉及」凑数。

命中必答条件的那几类，结论写在本节；跟具体小节强相关的（金额精度 ↔ 4.2 字段表、API 兼容 ↔ 4.5、消息乱序 ↔ 4.0 生命周期、缓存与事务 ↔ 4.1），在两边互指，不各写一份。

## 5 · 测试清单

`| # | 测什么 | 判据 |`。判据要可判定——"断言 X 表只多一行"，不是"验证功能正常"。

必有的几类：幂等（同一输入两次）、失败分支各一条、跨租户隔离、只增不改的表用受限角色直接改应报错、**把某个下游换成空实现主流程仍跑得通**。

## 6 · 已知技术债

本次明知不理想但本期接受的东西。每条四段：

| 是什么 | 为什么本期接受 | 什么时候必须还 | 不还会怎样 |

典型：某状态字段一期恒定值、某费率一期恒 0、某校验恒放行、某枚举值在字典里但本期没有任何转移会产生它。

**不归拢成一节，将来没人知道这些是有意为之还是忘了做。**

## 7 · 坑清单与技巧表

**这是全局清单的唯一正文所在。** 执行手册每任务第 7 段「本任务的坑与关注点」从这里挑三五条，只挑不复述。

**坑清单**——三段式（症状 / 原因 / 正确写法），形状与收录判据见 `writing-shapes.md`。来源两处：阻碍分级里的 ⚪ 口径陷阱，以及现状核对时发现的"不报错但某天两处对不上"的写法。

**技巧表**——四列（场景 / 技巧 / 为什么这个场景适用 / 什么场景不要用）。**技巧不是想出来的，是三道检索捡出来的**（现状核对里可复用的既有做法、🟠 与 ⚪ 阻碍的处置方案、坑的「正确写法」升格），详见 `writing-shapes.md`。

两张表**跨轮次继承，只增补不重写**；作废的标 `已作废（第 N 轮）` 保留原文。

`S` 档不出本文档，这两张表落在执行手册的全局章节。

## 8 · 任务索引

`| 设计小节 | 由哪个任务落地 |` 两列。**这是设计与手册之间的对账锚点**——校验脚本比对两份文档的任务编号集合是否相等，缺一个就说明有设计内容没人做、或有任务没有设计依据。

**任务顺序与依赖不写在这里**，那是执行手册的地盘。这一节只回答"这段设计归谁实现"。

## 9 · 未决索引

**只留编号 + 一句话 + 状态**，正文在未决台账里。不复述。

## 10 · 反向同步清单

写代码时一定会发现设计文档、表设计、架构决策记录哪里错了。这一节规定发现后往哪回灌：

`| 发现的问题 | 要改哪份文档的哪一节 | 要通知谁 | 状态 |`

**禁止就地改代码不回灌**——那是代码和文档分叉的起点。

## 通用纪律

1. **数字从表格派生，不写常数。** 条数、任务数、接口数写"以下表实际行数为准"。写死了，改了表忘了改数字就漂移。
2. **锚点可校验。** 类名、方法名、文件路径、表名、列名一律用反引号包起来，校验脚本靠它对账。
3. **每个非显然的决定带一行「选了 X；备选 Y，放弃因为 Z」。** 不写成大段对比表，一行。缺了这一行，三个月后没人知道当时是权衡过还是没想到。
4. **跨文档一致。** 同一个编号、字段、枚举，在所有文档里只能有一个版本。
5. **正文不留没带信息的句子。** 铺垫、过渡、复述上一节、解释读者基线内的概念、空形容词——一律删。
   但**该长就长**：字段表、DDL、枚举全部取值、失败分支、证据路径属于[不可压缩清单](prose.md)，压缩它们就是在制造盲测缺陷。规则与抽检做法见 `prose.md`。
