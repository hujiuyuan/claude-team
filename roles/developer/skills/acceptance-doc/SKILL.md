# 验收文件

被验对象：$ARGUMENTS

验收文件和设计文件一对一，只回答“怎么证明它做对了”。**验收的第一依据是需求文档，设计文件是第二依据**：只对着设计写，证明的只是“实现符合设计”，设计漏了或改歪了需求，验收也跟着漏。设计内容不复制，只引用：复制会让两处各自漂移。

## 开始前

1. 找本项目的“项目绑定”文件（先看项目 CLAUDE.md 里的指针，再找 `acceptance/` 或 `.claude/` 下的绑定文件）。字段见 `binding-template.md`。找不到就按该模板问我要，不要自己猜路径和编号。
2. **先读需求**：按绑定文件找到被验对象在需求文档里对应的页面或条目，把其中每条规则、每个异常、每个数据来源与写入的说明，带原编号逐条列成清单。需求文档找不到落点的（定时任务、消息消费常见）在回链写“需求无落点”，并说明验收只能依据设计。
3. 再读被验的设计文件、它引用的错误码表。
4. 逐条把需求清单对到设计：设计覆盖了的、设计没覆盖的、设计与需求写法不一致的，分别记下（见模板“需求对照”和“设计与需求差异”）。
5. 判断触发方式（下表），不同方式“操作”和“期望”的写法不同。

## 触发方式

| 触发方式 | “操作”列写 | “期望”列能写的可观察物 |
|---|---|---|
| 外部接口 | 请求要点（哪个字段给什么值） | 状态码、错误码、响应字段、落库行、发出的事件 |
| 服务间接口 | 以调用方身份发的请求要点 | 同上，另写调用方拿到的结果是否符合约定 |
| 定时任务 | 怎么触发：等调度 / 手动触发 / 先造出满足条件的数据 | 命中了哪些行、状态怎么变、没命中的行不变、重复跑一次的结果、审计留痕、告警 |
| 消息消费 | 投递什么事件（载荷要点） | 落库行、同一条重复投递的结果、该订阅与不该订阅的事件各自的处理、失败去向 |

一份设计文件里有多个任务或消费者时，验收项表加一列“单元”，仍是一份验收文件。

## 写法规则

- 验收项先从需求条目推出，再用设计文件补细节（错误码、字段名）。需求里有而设计里没有的，也要写验收项，“出处”写需求条目，并在“设计与需求差异”登记缺口；不许因为设计没写就丢掉。
- 需求条目属于页面表现、交互、文案的（前端范围），在需求对照里标“前端验收，不在本文件”，不写进验收项。
- 设计与需求写法不一致（名字、数值、行为）时，不自行裁决，两边原文位置都登记到“设计与需求差异”。
- “期望”只写能观察到的结果，不写“应当正确处理”这类无法判定的话。
- 覆盖：成功路径；设计里每个“不许……”各一条；接口类每个错误码各一条；定时任务要有命中、未命中边界、重复执行；消息消费要有每个订阅事件、重复投递、不订阅的事件不处理。
- 每条验收项的“出处”列指向设计文件的节或错误码表行，读的人能回查。
- 验证命令：没空跑过的如实标“未跑”，不要写得像跑通了。已有自动化测试覆盖了哪几条，读过测试代码才能填；没读过就写“未核”。
- 没有落点的内容（例如定时任务在需求文档里没有出处）按绑定文件的写法标出，不编出处。
- 不写真实口令、密钥；测试数据说明怎么造。

## 模板

```markdown
# <被验设计文件编号> · <中文名> · 验收

`<触发方式>`　`<触发一行>`

## 0 回链
设计文件路径；需求文档页面与行号范围。

## 1 需求对照
被验对象在需求文档里的每一条规则、异常，一行一条：
| 需求条目（原编号） | 内容摘要 | 去向 |
|---|---|---|
去向三选一：对应验收项编号 / 前端验收，不在本文件 / 设计缺口（见第 7 节）。

## 2 前置与依赖
依赖的接口、表、配置、上游事件、其它任务；测试数据怎么造。

## 3 验收项
| 编号 | 单元 | 场景 | 前置 | 操作 | 期望 | 出处（需求条目 + 设计节） |
|---|---|---|---|---|---|---|

## 4 验证方式
命令（注明从哪个目录跑、是否已空跑）；已有自动化测试对应哪几条，没有的标“手工”。

## 5 不验什么
范围外、由别的验收文件负责的，写指针。

## 6 提交信息
一行，沿用项目的提交风格。

## 7 设计与需求差异
需求有而设计没有；设计有而需求没有；两边写法不一致。每条给两边原文位置。没有就写“无”，不要省略这一节。

## 8 状态
对应设计版本；验收结论（未验 / 通过 / 不通过 原因）。
```

## 收尾自查

- [ ] 需求条目逐条有去向，没有漏项
- [ ] 没有复制设计文件里的判定条件、字段说明
- [ ] 每个错误码或每个“不许……”都有对应验收项
- [ ] 每条验收项有出处
- [ ] 验证命令的“是否空跑”如实标注
- [ ] 路径和编号都来自项目绑定文件，不是自己猜的
