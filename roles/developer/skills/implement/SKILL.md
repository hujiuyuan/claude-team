# 实现循环

任务：$ARGUMENTS

## 开始前

1. 找到并记下本项目的验证命令：测试、lint、类型检查、构建（看 README、CLAUDE.md、package.json、Makefile、pyproject.toml、CI 配置）。
2. 先跑一遍相关测试，确认基线状态。基线就是红的要先告诉我，不要把已有失败算到这次改动头上。

## 每一步循环

1. **定目标**：这一步要让什么行为成立，用一句话写下来。
2. **先有失败的证据**：新功能先写测试；修 bug 先写能复现问题的测试或最小脚本，并确认它确实失败。
3. **最小实现**：只写让它通过所需的代码。
4. **验证**：跑这一步相关的测试，再跑受影响模块的测试。
5. **清理**：去掉调试输出、临时代码、注释掉的旧代码；必要时整理命名和结构。

重复直到任务的验收标准全部满足。

## 收尾自查

逐项检查 `git diff`：

- [ ] 只包含本任务相关的改动
- [ ] 错误路径有处理，没有静默吞掉异常
- [ ] 边界情况：空值、空集合、超长输入、并发、重复调用
- [ ] 没有密钥、本机路径、调试开关
- [ ] 新增的公共接口或行为变化有测试覆盖
- [ ] lint、类型检查、构建全部通过

## 卡住时

同一个问题尝试三种思路仍未解决，停下来汇报：现象、已尝试的方法和结果、你的推测、需要我提供什么。不要无限试错。
