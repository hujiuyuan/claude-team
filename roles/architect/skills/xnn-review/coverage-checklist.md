# PRD 覆盖审计清单

立场：视角审计员（覆盖）。以 PRD 为唯一依据，定位遗漏。

## 步骤

1. **编号**：给 PRD 范围内每个条目编一个稳定 ID（章节号 + 序号，例如 `3.2-4`）。PRD 自带编号的，沿用它的编号。
2. **追溯表**：PRD 条目 → X 文件（功能点位置）→ YY。
3. **逐条判定**，每条都要引用 PRD 原文位置：
   - **已覆盖**：写出 X-NN 中对应的位置。
   - **部分覆盖**：写明缺什么。
   - **未覆盖**：按第 4 步判定落点。
4. **落点判定**：
   - 遗漏属于已有资源的操作、字段、状态或规则 → **补本 X-NN 功能点**。
   - 遗漏是一个有独立生命周期、能单独交付的资源，或者横跨多个 X → **新增 X 文件**。这种情况要走辩证裁决。
   - 遗漏属于另一个已有 X 文件的范围 → 标出那个 X 文件，不在本 X 里补。
5. **反向检查**：X-NN 里有、PRD 里没有的功能点，标“超出 PRD”。由裁判裁决保留还是删除；闭环需要的通常保留。
6. **语义扩展检查**：对每个已覆盖的 PRD 条目，逐项列出设计在原文之外增加的行为（覆盖了哪个字段、扩展了哪个状态、改变了什么含义）。每一项都要在 X-NN 的“假设与裁决”里单列一行，标“解释”。
7. **隐含需求**：PRD 没写，但闭环、权限、审计等必需的，不在这里判定，转给闭环审计员，并在“清单外发现”里提一句。

## 输出

| 视角键（PRD 条目 ID） | PRD 原文位置 | 判定 | 本 X-NN 位置 / 落点 | 建议修法 | 候选修法数 |
|---|---|---|---|---|---|

最后附：覆盖计数（已覆盖 / 部分覆盖 / 未覆盖 / 超出 PRD）、语义扩展清单和清单外发现。

## 降级

PRD 没有读到时，不得给出“已覆盖”或“无遗漏”，只输出待核对清单。
