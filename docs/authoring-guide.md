# 角色与技能写作指南

## 角色提示词（agents/<角色>.md）

**frontmatter**

- `name`：与文件名一致。
- `description`：Claude 靠这句话决定什么时候把任务交给这个角色。写“它是谁 + 什么场景交给它 + 关键限制”，例如“代码评审。代码写完、合并前审查改动的正确性和安全性。只读。”
- `tools`：最小够用。只读角色不给 Write/Edit；需要按需加载技能时保留 `Skill`。省略 `tools` 表示继承全部工具。
- `skills`：预加载的技能，写成 `<插件名>:<技能名>`，例如 `team:house-rules`。每个角色都应包含 `team:house-rules`。
- `model`：一般用 `inherit`，跟随会话模型。
- `color`：red / blue / green / yellow / purple / orange / pink / cyan，便于在界面上区分角色。

**正文结构**（照 `templates/role/agents/` 里的模板）

1. 一句话身份：“你是我的 xx，负责 yy。”
2. 工作流程：编号步骤，每步写清楚产出是什么。
3. 输出格式：交付物长什么样。
4. 原则：做判断时依据的取舍，写成可执行的规则。
5. 边界：明确不做什么。
6. 我的习惯：主人的个人偏好，持续用 `/team:learn` 补充。

**写法要点**

- 写规则不写感想：“方案里必须有回滚步骤”，而不是“要重视回滚”。
- 给原因：一句话说明为什么，角色在边界情况下才能举一反三。
- 不重复 house-rules 里的通用内容，只写这个角色特有的东西。
- 正文控制在 100 行以内；长的模板、清单拆到技能里。

## 技能（skills/<技能>/SKILL.md）

- 一个技能 = 一个可重复的流程、模板或清单。
- `description` 写清“做什么 + 什么时候用 + 用户会怎么说”，这决定它会不会被自动调用。
- 只想手动触发（例如会提交、发布的流程）时加 `disable-model-invocation: true`。注意：这样的技能不能放进 agent 的 `skills:` 预加载列表。
- 用 `$ARGUMENTS` 接收 `/角色:技能 <参数>` 传进来的参数。
- 长模板、示例、参考资料放在技能目录下的其他文件里，在 SKILL.md 中用相对链接引用。

## 放哪里

| 内容 | 位置 |
|---|---|
| 所有角色都适用的习惯 | `roles/team/skills/house-rules/SKILL.md` |
| 某个角色的身份、流程、偏好 | `roles/<角色>/agents/<角色>.md` |
| 某个具体流程的步骤、模板、清单 | `roles/<角色>/skills/<技能>/SKILL.md` |
