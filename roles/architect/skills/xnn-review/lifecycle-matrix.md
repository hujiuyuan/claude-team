# 生命周期闭环矩阵

立场：视角审计员（闭环）。**后端必须闭环；前端可以不提供，但对应的后端能力必须有。**

## 1. 资源 × 操作矩阵

对 X-NN 涉及的每个资源或实体画一张表。每格填：

- **后端**：✅ 提供（写接口或事件名）/ ❌ 缺失（缺失即阻塞问题）
- **前端**：✅ 提供 / ➖ 不提供（写理由）

| 操作 | 后端 | 前端 | 说明 |
|---|---|---|---|
| 创建 | | | |
| 查询：详情 | | | |
| 查询：列表、筛选、分页 | | | |
| 修改 | | | |
| 状态流转 | | | 每个状态转换单独一行 |
| 启用 / 停用 | | | 必须成对 |
| 失效 / 过期 | | | 写明是自动还是手动、由什么触发 |
| 撤销 / 回收 | | | 与授予、发放成对 |
| 删除或归档 | | | 按下面的删除策略填写 |
| 恢复 | | | 软删或归档后能否恢复；不能恢复要写理由 |

## 2. 横切列（每个资源都要填）

| 项 | 要求 |
|---|---|
| 权限点 | **必检**：每个后端操作都要有对应的权限点 |
| 审计事件 | **必检**：每个改变状态或数据的操作都要有对应的审计事件 |
| 幂等 | **适用时必填**：创建、发放、外部回调、重试等场景；不适用时写理由 |
| 并发控制 | **适用时必填**：版本号、乐观锁等；不适用时写理由 |
| 删除策略 | **必须明确**：默认软删加归档；选硬删要写理由 |

目标仓库的样板已有约定的，以样板为准。

## 3. 状态机检查

- 列出所有状态和转换（文字或 mermaid 状态图）。
- 每个非终态至少有一条出边；每个状态都能从初始状态到达；不存在进去就出不来的状态。
- 正反操作成对：授予 ↔ 撤销，启用 ↔ 停用，冻结 ↔ 解冻，创建 ↔ 删除或归档，等等。
- 失效、过期、异常中断（超时、失败、外部回调丢失）都要有去向。

## 4. 判定

- 后端缺任何一个必检项 → 阻塞，落点“补本 X-NN 后端功能点”。PRD 没写的，标“PRD 未体现”。
- 前端缺 → 不阻塞，标“前端不提供”并写理由。
- 死状态、不可达状态、不成对的操作 → 阻塞。
