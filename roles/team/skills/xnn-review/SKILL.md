# X-NN 需求分析规划

参数：$ARGUMENTS

主会话担任主持人。参与者：

- `architect:architect`：需求基线、YY 拆分。
- `team:debater`：视角审计员、盲审分析员、代言人。
- `team:judge`：裁判。
- 主会话：主持，把产出复制到目标目录。

清单和模板（审计员要读的是**文件全文**，主持人只把路径交给它们，不改写、不压缩）：

- `${CLAUDE_SKILL_DIR}/coverage-checklist.md`：PRD 覆盖
- `${CLAUDE_SKILL_DIR}/lifecycle-matrix.md`：生命周期闭环
- `${CLAUDE_SKILL_DIR}/executability-checklist.md`：可执行性
- `${CLAUDE_SKILL_DIR}/xnn-skeleton.md`、`${CLAUDE_SKILL_DIR}/yy-template.md`：没有样板时用的通用骨架

## 规则

- **遇到问题按 house-rules 分级**：L0 查证；L1 一律走 `team:deliberate`；只有 L2 才问用户，并且在阶段末一次问完。
- **运行目录**：`~/.claude-team/runs/<YYYYMMDD>-<X-NN>/`。所有子代理都把完整输出原样写进主持人指定的 `rounds/` 文件（`team:deliberate` 第 3 节；子代理没写出时按该节的补救落盘处理），下一轮只转交文件路径，不转交摘要。
- **进度与续跑**：主持人在每个断点更新 `<运行目录>/progress.md`。断点：G1–G5 每个关卡关闭时、S5 每一波结束时、S8 每次修订结束时、S9 每一轮结束时。内容：当前步骤；已完成的轮次，逐个链接到 `rounds/` 文件；下一步；进行中的调用及其指定输出路径；`pool.md` 和决策日志的最后编号。运行被中断后（时间上限、后台等待上限、会话崩溃），续跑的第一步是读 `progress.md`，逐项核对所列文件是否存在；进行中的轮次，输出文件已由子代理写出、或满足 `team:deliberate` 第 3 节补救落盘条件的保留，其余整轮重跑。`progress.md` 与 `rounds/`、`pool.md`、决策日志不一致时，以后三者为准。原因：时间上限只决定停在哪个断点，不能减少任何审查；续跑靠文件，不靠临时写的提示词。
- **审计发现的裁决拆批**：S4、S9 的裁判一次要裁的发现超过 8 条时，按 `team:deliberate` 第 8 节拆批：每批不超过 8 条；同一视角键（S4）或同一个 YY（S9）的发现不拆到两批；各批并行，最后做一次跨批一致性检查。跨批检查必须把多批共用的约定写成唯一文本（编号加全文），各批的修订指令只引用这份文本，不各写一版。原因：一个裁判一次裁几十条，是这一阶段最长的单步；共用约定由跨批检查统一。
- **主持人中立**：遵守 `team:deliberate` 第 3 节的中立规则。只列出条目，不给条目定性，不预先建议“可以简化”“不必复核”。
- **只读角色不写目标仓库**：目标目录里的文件只能由主会话写（用 `cp` 从运行目录复制，或用 Write），修订轮也一样。
- **调用子代理时不传 `name`**。
- **公司内容不进 claude-team 仓库**。样板、PRD、产出只放在目标文档仓库和本机运行目录。

## 步骤

### S0 准备与降级判定

**定位输入**：先看参数；没有就读当前仓库的 CLAUDE.md，再在仓库里查找。

- PRD
- 设计文档目录，以及同目录下已有的 X-NN 和 X-NN-YY 样板
- 代码目录

**格式摘要**：从样板里提取 X-NN 和 YY 的章节结构、编号与命名规则，存进 `<运行目录>/format-summary.md`。读不到样板时，用通用骨架，并在产出开头注明“样板未读”。

**三个降级标志**：PRD 未读、样板未读、代码未读。

- **PRD 读不到属于 L2**：问用户要路径，不能硬做。用户坚持继续的，进入**待核对模式**：不得给出“无遗漏”或“覆盖完整”的结论。
- **代码读不到**：在 X-NN 的“假设与裁决”里集中写一条**技术栈假设**（数据库、ORM、Web 框架、日志组件、测试框架、目录结构）。YY 据此精确到 SQL 和函数。第一个 YY 的第一个动作必须是“对照代码核对技术栈假设，不符则停止，回到 S8”。产出开头注明“未对照代码”。

### S1 需求基线（`architect:architect` 子代理，输出写到 `rounds/S1-architect.md`）

- 给 PRD 范围内的条目编稳定 ID。
- 建追溯表：PRD 条目 → 现有 X 文件和功能点 → YY。
- 列出实体清单，写现有设计摘要。
- 歧义或冲突用“待裁决”块返回，主持人编号后放进 `pool.md`。

**G1 关卡**：范围内每个 PRD 条目都有 ID 和追溯状态。

### S2 三视角盲审（3 个 `team:debater` 并行，互相看不到对方）

| 立场 | 清单（给路径，自己读全文） | 输出文件 |
|---|---|---|
| 视角审计员（覆盖） | coverage-checklist.md | `rounds/S2-覆盖.md` |
| 视角审计员（闭环） | lifecycle-matrix.md | `rounds/S2-闭环.md` |
| 视角审计员（可执行性） | executability-checklist.md 的 X-NN 部分 | `rounds/S2-可执行性.md` |

每条发现都要写明：视角键（PRD 条目 ID / 资源×操作 / 决策点）、出处、建议修法、候选修法数、是否需辩论；最后附“清单外发现”。

### S3 交叉校验（1 轮）

- **合集**：主持人按视角键合并，存为 `audit/merged.md`。每条必须保留：来源审计员、各方原始候选数、任何一方标的“需辩论”、原文路径。
- 3 名审计员各拿到合集路径，逐条写“支持 / 反驳 / 补证据”，并检查别人的修法会不会破坏自己负责的那一维。输出写到 `rounds/S3-<视角>.md`。
- 不得引入新论题。新问题先进 `pool.md` 并编号。

### S4 裁决（`team:judge`，输出写到 `rounds/S4-judge.md`，摘要追加到 `verdicts.md`）

逐条给出结论（按 `team:deliberate` 第 6 节格式）、能否直接使用，以及落点：

- 补本 X-NN 功能点
- 新增 X 文件
- 改 YY
- 后置建议
- 超出范围

**固定裁决规则**：

- **后端闭环是硬约束。** PRD 没写的反向操作或必检项，记为“补本 X-NN 后端功能点”，并标注“PRD 未体现”。
- **前端可以不提供**，但要写理由。
- **新增 X 文件的条件**：遗漏的是一个有独立生命周期、可以单独交付的资源，或者横跨多个 X。否则补进本 X-NN。
- **防止过度设计**：每个新增的功能点、接口、错误码、端口、配置项或发布门槛，都必须回链到一个 PRD 条目，或 lifecycle-matrix 的一项必检内容（成对操作、权限点、审计事件、幂等、并发、删除策略、失效与异常去向）。两样都回链不上的（例如限频、额外安全头、日志脱敏、参数细则、预检端口），一律裁为“后置建议”：只写进父文档的“后置建议”小节，不进 YY，也不进发布门槛。确属安全底线的，走 L2。
- **直裁与进 S5 的界限**：裁判只能直接裁决 L0 条目，即结论能由上面的固定裁决规则、已定决策（决策日志 ID）、PRD 条目，或本身写明答案的引文“路径:行号”唯一推出的条目；日志记 L0，出处写这条规则或引文。其余条目都是 L1，进入 S5，从 T1 起步，包括：任一审计员的候选修法数为 2 个及以上、而上述出处推不出唯一答案的；要按优劣在候选之间取舍的；要裁判新编修法的；审计员标了“需辩论”或在 S3 被反驳过、而上述出处推不出唯一答案的。不让条目进 S5 的理由只能是上述 L0 出处。原因：house-rules 规定 L1 一律由 2 名盲审分析员加裁判；审计员不按 ①–⑧ 分析，裁判单独裁 L1 没有例外。

**G2 关卡**：每条发现都有裁决。

### S5 子辩

- 需辩论的条目按 `team:deliberate` 处理：从 T1 起步，审计员原文路径并入共享证据包，按第 4 节逐题决定是否升 T2。互相牵连的条目可以合成一场，按 `team:deliberate` 第 4 节第 5 步的规则处理。不设场次上限。
- **新增 X 文件的辩论只决定“要不要新增”和“边界怎么划”**，不决定“建不建骨架”“定不定编号”。这两件由 S7 按规则执行，不能作为候选方案。

### S6 阶段末汇总 1

- `pool.md` 里剩下的问题，按 `team:deliberate` 逐条裁决。
- 待拍板清单（L2）按 `team:deliberate` 第 9 节的 9 个字段逐条写好，**此时先输出一次**，等待期间按默认值推进。

**G3 关卡**：`pool.md` 里没有“待裁决”，并且每一行都链接到决策日志里具体的 ID。

### S7 写 X-NN（主会话）

- **只能使用 `verdicts.md` 里已有的结论。** 写作中遇到裁决没覆盖的项（特别是 lifecycle-matrix 的必检横切项），先进 `pool.md` 走 T1，裁决后再写。
- 按样板格式写；没有样板时用 xnn-skeleton。必须包含：PRD 追溯表、生命周期矩阵、状态机、横切项、子任务列表、“后置建议”小节、“假设与裁决”小节、降级标注。
- **判定要新增的 X 文件，当次就建骨架**：
  - 编号按下面“编号与追溯”的规则直接取，不得以“编号没有依据”为由推迟。
  - 骨架只包含：标题、PRD 来源条目、与本 X 的接口和依赖、标注“待 xnn-review”，不写设计结论。
  - 这一步属于本次被要求的范围，不适用 house-rules 里“范围外的不顺手改”。
- 写入目标目录前，先把草稿写进运行目录；写入后执行 `git status` 确认只有预期的文件发生变化。

**G4 关卡**：

- 矩阵每一格都填了。用“由其他接口覆盖”作为理由的格，写明了覆盖的状态范围（见 lifecycle-matrix）。
- 状态机里每个非终态都有出边，所有状态都可达，没有死状态。
- “假设与裁决”里的每一行，都能在决策日志里找到对应 ID。

### S8 拆 YY（`architect:architect` 子代理）

- 每个 YY 一个文件，一个 YY = 一次独立提交。architect 把**完整正文**写进 `rounds/S8-yy/<文件名>.md`，主会话用 `cp` 复制到目标目录。S8 的修订要改写已有 YY 时，主持人先把当前版本复制到 `rounds/S8-yy-history/<轮次>/`，主路径 `rounds/S8-yy/` 不变。原因：原地改写后，改写前的版本无法回放和核对。
- 按样板格式写；没有样板时用 yy-template。动作写到：文件或模块、接口和字段、错误码、迁移和回滚、测试、验证命令。
- **粒度**：一个 YY 同时包含基础设施（端口、注册表、守卫、测试夹具）和业务接口时，优先拆成“基础设施 YY”和“业务 YY”。改动清单超过约 8 项时，YY 里要写明不拆的理由。
- **条件性 YY**：依赖还没交付的外部 X 的，标“条件性”，并写明启动条件，以及开工前需要替换的推断名和未知项清单。
- 拆分中需要做的设计选择，用“待裁决”块返回，主持人立即走 `team:deliberate`（这类问题会阻塞下游）。

### S9 YY 可执行性复审

- 只重跑“可执行性”这一个视角：审计员按 executability-checklist 的 YY 部分逐个 YY 检查，输出写到 `rounds/S9-<轮次>-可执行性.md`；再由 `team:judge` 裁决，超过 8 条按“审计发现的裁决拆批”执行。
- **裁判的直裁范围同 S4**：只能直接裁决 L0 条目；L1 条目进 `pool.md`，与本轮其他进池条目放在同一张卡上走 T1。
- **每轮裁决必须有“下一轮复审范围”一节**：逐个 YY 列出改动处、联动处和理由；主持人检查命令判“不符”的项自动列入。裁决漏写这一节的，下一轮按全量复审。
- **循环到通过为止**：不合格的回到 S8 修改。第 1 轮全量复审。第 2 轮起，审计员必须覆盖上一轮列出的范围，范围外不要求重审；同时对全部 YY 逐个核对 G5 的三项条件。范围外的新发现照常报告，先进 `pool.md` 编号再裁决，不重开全量复审。直到明确写出“通过”。grep 自检只能作辅助，不能代替复审。
- 裁判给出的检查命令要全部执行，输出存进 `rounds/`。

**G5 关卡**：只能由审计员或裁判写出的“通过”关闭，主会话自评不算。写出“通过”的那一轮，审计原文里必须有对全部 YY 的 G5 三项核对（第 1 轮的全量复审算）。条件：

- 每个可直接执行的 YY，待定决策点为 0（技术栈假设除外）。
- 每个 YY 都能独立提交、独立验证。
- 矩阵每一格都映射到某个 YY，或注明“前端不提供”。

### S10 交付

- **交付前格式自检**：YY 文件名里的标题和一级标题一致（只允许去掉文件名中的非法字符）；每个二级标题前有空行。
- 把 X-NN、YY 和新增 X 的骨架写进目标目录。**不提交、不推送**：用户抽检后明确说“提交”时，再按目标仓库的规范提交并推送。
- 按 house-rules 的格式汇报。**计数口径固定**：
  - PRD 条目：已覆盖 / 部分覆盖 / 未覆盖（未被任何 X 承接的单独列出）。
  - 新增功能点：S4、S5 落点为“补本 X-NN 功能点”的条目，逐条列出 ID，分开标注“PRD 未覆盖”和“PRD 未体现”。
  - 新增 X 文件：判定 N 个 / 已建骨架 N 个，逐个列出路径。两个数不相等，就回到 S7。
  - YY：可直接执行 N 个 / 条件性 N 个。
  - 后置建议：N 条。
  - 关卡结果 G1 到 G5、矩阵格数。
- 遗留问题：降级标注、技术栈假设、待拍板清单（9 个字段完整）、运行目录路径。

## 编号与追溯

- 新增 X 文件，优先沿用样板仓库的编号惯例；没有惯例时，取同模块下一个未用的编号。
- YY 编号只增不重排。废弃的 YY 标“已废弃”，不删除。
- X-NN 拆分或合并后，旧编号作为别名保留在追溯表里。
