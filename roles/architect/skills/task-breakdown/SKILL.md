# 任务拆解

对象：$ARGUMENTS

## 拆分规则

- **可独立交付**：每个任务完成后代码可以合并，主干保持可用；必要时用开关或兼容层过渡。
- **可验证**：每个任务都有明确的验收标准，最好能用一条命令或一个测试证明。
- **粒度**：一个任务大约是一次评审能看完的改动（几百行以内）；更大的继续拆。
- **顺序**：先打通最小端到端链路，再逐步补全；高风险、不确定的部分尽早做，先验证假设。
- **依赖最少**：能并行的标出来，方便多个 developer 同时做。

## 输出格式

```markdown
| # | 任务 | 改动范围 | 依赖 | 验收标准 | 规模 |
|---|---|---|---|---|---|
| 1 | <动词开头的一句话> | <模块/文件> | - | <怎么证明完成> | S/M/L |
| 2 | ... | ... | 1 | ... | ... |

可并行：2 和 3 可同时进行。
关键路径：1 → 2 → 4。
最先验证的风险：<哪个任务验证哪个假设>
```

规模参考：S = 一小时内，M = 半天，L = 一天。超过 L 的继续拆。
