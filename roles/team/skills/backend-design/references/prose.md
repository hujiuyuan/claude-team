# 正文密度

**密度管的不是长度，是每句话有没有带信息。**

设计文档该长就长——一份 `L` 档正文几千字是正常的。字段表、DDL、枚举值域、失败分支，少一个字都是缺陷。按字数扣分会逼着去删这些，那正是盲测判死的东西。

判据一句话：**删掉这句，读的人会少知道哪件具体的事？答不出具体的，就删。**

---

## 一、不可压缩的是「事实」，不是围着事实的论述

**事实有确定形态**，删了读的人就没处查：

- **表格的行与格**
- **代码块**——DDL、方法签名、分步伪码
- **有出处的东西的原文**——列注释里的单位、需求原件的原句、代码里的真声明。**照抄，不转述**

⚠️ **这一节是否定式的：不是「这些必须写」，是「删的时候绕开这些」。** 本次不涉及枚举就没有枚举，不存在「省了」——**不要为了让清单看起来齐全而去编一节**。

下表每条对应一个真实缺陷编号（目录见 [blind-test.md](blind-test.md)）。

| 删了会怎样 | 编号 |
|---|---|
| 字段表第一列不是真实键名，中文进了第一列 | A1 |
| 字段类型写成「A 或 B」 | A2 |
| 字段表与 DDL 推给了派活范围外的另一份文档 | A3 |
| 新建表只给概念列，没给列名 / 类型 / 可空 | A4 |
| 枚举只给中文档位名，没给机器可读取值 | G4 |
| 枚举取值与列注释值域对不上 | D2 |
| 列注释里的单位与语义没抽出来（「0.6 表示 0.6%」） | D1 |
| 列注释里的反向警告没带进来（「不要照 Y 写」） | D5 |
| 数量断言没给得到这个数字的命令 | B3 |
| 列举没逐项给处置：校验四项只写一项、状态守卫漏档位、只写失败分支、阈值没说清 `0` | E1–E5 |
| 「照 X 抄」没写清 X 的用法边界 | G3 |
| 时点、时区没写到用哪个常量 | G2 G5 |
| 幂等只写「要幂等」，没写用什么机制 | F2 |
| 时序图没画失败分支 | — |
| 结论没带证据（文件路径 + 行号，或需求出处） | — |
| 跨任务接口速查节缺签名 / 枚举全值 / 错误码段位 / 别人要建的表的列清单 | — |
| 术语表「不是什么」列空着 · 坑没写三段式 · 技巧缺「什么场景不要用」列 | — |

### 最常见的错法：把事实单开一段，然后围着它写作文

**反例**（表设计里真实出现过）：

> `UK(tenantId, templateId, userId)` 是**「同券限领一次」的唯一实现**，同时是领取接口的**幂等键**——并发重复领取靠它挡，捕获唯一键冲突后返回「已领取」，**不要靠先查后插**。

拆开看：

- 前半句「是限领一次的实现，也是幂等键」是**事实**，它本来就该在字段表「索引」那一格里
- 后半句「并发怎么挡、冲突怎么处理、不要先查后插」是**实现建议**，那是伪码的位置

整段另起的结果是：**一格的内容膨胀成一段，而那一格还空着。**

### 判据：这句话能不能塞进某个表格的某一格

| 能不能塞进格子 | 是什么 | 怎么办 |
|---|---|---|
| 能 | 事实 | **塞进去，不另起段。** 一格一句话，不超 60 字 |
| 不能，是结论 | 结论 | 留在正文 |
| 不能，是推导 / 理由 / 「为什么选它不选别的」 | 论证 | **删** |
| 不能，是反事实后果 | 踩坑记录 | **删**，除非**失败是静默的**——见下 |

**反事实后果只留一种：失败不报错的那种。**

「不设租户值会查不到任何一行**而且不报错**」要留——「失败是静默的」这件事决定了读的人会不会为它写测试，它是操作性约束，不是战争故事。
「顺序反了会导致名额多扣一个，因为并发下回滚窗口内别人可能已经读到那行」——后半截是推导，删掉，只留「顺序不能反，反了会多扣一个名额」。

## 二、该删的八类

| # | 类型 | 长什么样 | 怎么办 |
|---|---|---|---|
| 1 | **铺垫与过渡** | 「为了更好地理解本次设计…」「接下来我们将详细阐述…」「综上所述」 | 直接删，不用替代 |
| 2 | **复述上一节** | 每节开头重述一遍背景 | 删；真要指，写小节编号 |
| 3 | **解释读者基线内的东西** | 什么是接口、什么是索引、什么是 REST、什么是事务 | 删。基线见 `writing-shapes.md` |
| 4 | **空形容词与程度词** | 「非常重要」「极其关键」「相当复杂」「良好的扩展性」「优雅」 | 删。要么给数字，要么不写 |
| 5 | **一句拆三句** | 「这个字段很重要。它用来标识订单。没有它就分不清订单。」 | 合成一句：「`orderNo` 是订单唯一标识」 |
| 6 | **客套与免责** | 「需要注意的是」「值得一提的是」「当然这只是建议」 | 删 |
| 7 | **散文装并列项** | 三个并列条件写成三段话 | 改成表格或编号列表 |
| 8 | **围着事实写作文** | 把表格里一格能装下的事实另起一段，再补一段推导 | 塞回格子里，推导删掉。判据见第一节 |

**第 3、4 类最费字**（AI 写后端设计文档时平均占正文三成以上），**第 8 类最难自查**——它长得像正文，实际是把表格的内容摊开了写。

## 三、三条已经在别处写过的密度规则

不是新规矩，集中放在这里便于一起过：

- **数字从表格派生，不写常数**（`design-doc.md` 通用纪律 1）
- **决定写一行「选了 X；备选 Y，放弃因为 Z」，不写大段对比表**（`design-doc.md` 通用纪律 3）
- **十阶段里不适用的格合并成一行写掉，不逐格重复凑字数**（`entry-points.md`）

## 四、密度抽检——步骤 8 自检里跑

两道，都要过。

### 1 · 禁用语 grep

```bash
grep -nE '为了更好|综上所述|总而言之|总的来说|接下来我们|下面我们|首先我们|值得注意的是|需要注意的是|值得一提的是|众所周知|本节将|在本节中|可以说|不难看出|非常重要|极其关键|至关重要|良好的|优雅|健壮' 设计文档.md 执行手册.md
```

**命中即删**，不做例外判断——这些词在本类文档里没有合法用法。

### 2 · 删句抽检

随机抽三段正文（不抽表格、不抽 DDL、不抽伪码），逐句问：**删掉它，读的人会少知道哪件具体的事？**

- 答得出具体的东西（某个取值、某条路径、某个后果）→ 留
- 答的是「让读者理解得更好」「起承上启下作用」→ **删**

**判据：抽的三段里，一句都删不掉才算过。** 删得掉就删完重抽，直到过。

⚠️ **抽检只对第二节那八类动手，不碰第一节列的事实。** 抽到的段落里如果有字段表、签名、枚举取值、证据路径，跳过那一段另抽。

但**第 8 类要专门抽一遍**：挑三段正文，逐段问「这段里有没有哪句该在某个表格的格子里」。有就搬回去。

## 五、三档都适用

`S` 档不出设计文档，密度规则照样管执行手册正文；`M` / `L` 两份都管。

抽检粒度按档：`L` 抽三段，`M` 抽两段，`S` 抽一段。

## 接线（给元检查看的）

- **哪一步产出它**：步骤 8 自检的「密度抽检」，排在盲测之前。
- **哪一节收留它**：**不单独占节**——它是横切纪律，约束两份产物的全部正文。产物侧落点是设计文档「通用纪律 5」。本文件的两张清单（不可压缩的事实 · 该删的八类）是判据表，不是待填产物，元检查不必替它们找收留节。
- **横切四项**：不产出编号前缀 · 不进头部指纹 · **不改校验脚本**（12 项不变，密度靠本文件的 grep 与人工抽检兜）· 三档都出。
