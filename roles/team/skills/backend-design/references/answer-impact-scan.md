# 答复影响面扫描

**问题**：问了人、拿到答复、回灌进设计——然后答复本身引出了新问题，而没人扫出来。

**关键认识**：一条答复的影响面是**可枚举的**。答复总是落在某个锚点上——某张表、某个枚举、某条路径、某个字段、某个常量。顺着锚点做反向引用检索是机械操作，不是"再想一遍"。

"回灌后重跑一遍看看有没有新问题"是句空话，执行时就是草草扫一眼然后说没问题。**必须落成固定动作。**

---

## 一、八类锚点扫描表

答复改动了哪一类，就必须回扫对应位置。**逐条 grep，不靠回忆。**

| 答复改动了什么 | 必须回扫 |
|---|---|
| **接口路径** | 匿名访问白名单登记 · 权限点登记 · 前端调用处 · 路由覆盖测试 · 日志脱敏规则 |
| **枚举值域** | 数据库列注释 · 字典页渲染（锁定字典要全档位）· 多语言词条 · 状态机转移表 · 前端类型定义 · 测试里的穷尽断言 |
| **表结构 / 新增列** | 表设计文档（唯一真理源）· 唯一性约束登记 · 行级安全策略 · 字段级 GRANT · ER 图 · 溯源锚点 |
| **出参字段形状** | 前端类型定义与校验函数 · 契约测试 · 导出与报表 |
| **编号格式** | 编号生成器 · 编号规则文档 · **已发出的存量数据** |
| **状态机** | 转移表 · 终态判定 · 定时任务的过滤条件 · 按钮可用条件 |
| **事务边界 / 分层** | 架构约束测试 · 编号生成时机 · 审计落点 |
| **默认值 / 配置项** | 种子数据 · 配置页面 · 依赖它计算的地方 |

### 实例：这套真能抓到东西

**场景**：四张资金表启用了行级安全，不设租户值一行都查不到；而收银台和支付回调没有租户上下文。答复是"在四个端点路径上各加一段 `{tenantCode}`"。

按「接口路径」这一行回扫，扫出两条：

1. **匿名白名单要同步改** —— 四条路径形状全变了，而项目里有测试断言"白名单登记的集合必须恰好等于实际注册的端点集合"，不同步直接构建失败。这条是提醒。
2. **防枚举纪律当场破** —— 原有纪律是"token 无效、过期、已支付、系统故障一律同一个答案"。现在路径上多了一段 `tenantCode`，**这段写错时返回什么**？如果它的响应跟 token 无效不一样，等于对外泄露"这家租户存不存在"，纪律破在自己手里。
   **这是一条新的 🔴，原文档里根本不存在，是答复本身造出来的。**

第 2 条就是不扫必漏的那种。

## 二、答复留痕

每条答复记一行，三段：

```
答复内容 → 推翻了哪条既有结论 → 新引出哪些待查项
```

**"推翻了什么"这一段不能省。** 答复不只制造新问题，还会作废旧结论——比如某个编号格式被改掉之后，编号规则文档和编号生成器注释里写死的旧格式两处同时作废。不留痕就会在文档里留下两个互相矛盾的版本。

---

## 三、扫不出来的那一类，以及兜底

**这套扫描靠的是"答复落在已有锚点上"。** 如果答复引出的是一个代码和文档里都还不存在的全新概念，反向引用检索无从下手——没有东西可 grep。

**兜底**：每条答复回灌后强制回答一个问题：

> **这个答复引入了什么现在还不存在的东西？**

答"有"，就把它当成一个新的待设计项，**从现状核对那步完整走一遍**，而不是在文档里记一句话带过。

典型：某个配置值的答复是"按类型从交易设置取"，一 grep 发现全库根本没有交易设置这张表——那它就是一个完整的待设计项（要出 DDL、要定层级、要决定谁读它），不能一句"到时候建一张表"带过。

---

## 四、收敛判据与出口

**收敛 = 跑到不动点**：

> 连续**两轮**影响面扫描都零新增，才算收敛。任何一轮扫出新东西，就得再来一轮。

只看"🔴 清零"不够——🔴 清零的那一刻可能正好是新 🔴 刚被造出来还没扫到的时刻。

**出口（防死循环）**：

> 同一个问题**三轮**问答仍不收敛，强制降级：转 🟣 候补，或标"带假设推进"并把假设原文写进设计文档显眼处。

不许无限循环。三轮还问不清楚的，通常不是信息不够，是问题本身问错了。

---

## 五、改动型需求复用这张表

评估一个改动的**爆炸半径**用的是同一张八类锚点表：先定位现有实现落在哪几类锚点上，再逐类回扫谁受影响。

改动型需求多一条硬规则：**动手前先跑通现有测试**，改完再跑一次，红了的每一条都要解释——**是预期变更，还是踩坏了**。不解释就当踩坏了。
