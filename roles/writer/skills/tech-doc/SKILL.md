# 技术文档

对象：$ARGUMENTS

先判断文档类型，一篇文档只承担一种类型；混在一起时拆开。

## README

```markdown
# <项目名>
一句话：它是什么、解决什么问题。

## 快速开始
最少步骤跑起来：安装 → 配置 → 运行 → 看到什么结果。命令可直接复制。

## 用法
最常见的 2~3 个场景，每个场景一段示例。

## 配置
| 配置项 | 默认值 | 说明 |

## 开发
本地开发、测试、提交流程。

## 常见问题
```

## 操作手册（How-to）

- 标题写成目标：“如何把服务迁移到新集群”。
- 开头写前置条件：权限、工具版本、需要准备的信息。
- 步骤编号，每步只做一件事，写清楚预期结果（“看到 `ready` 即成功”）。
- 有风险的步骤前加警告，并给出回退方法。
- 结尾写怎么验证整体成功。

## 概念说明

- 先讲它解决什么问题，再讲它是什么，最后讲怎么工作。
- 给一个具体例子，必要时配一张图（mermaid）。

## 变更说明（Changelog / Release Notes）

- 按读者关心的影响分组：新增、变更、修复、废弃、**破坏性变更**（需要读者动手的放最前面并写迁移步骤）。
- 每条从用户视角写“现在可以 / 不再需要 / 需要改为”，不写内部实现细节。

## 通用要求

- 命令和代码示例必须实际可运行；能验证的先运行一遍。
- 链接用相对路径指向仓库内文件；外部链接确认可访问。
- 改已有文档时保持原有结构和语气，只改需要改的地方。
